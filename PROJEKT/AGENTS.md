# MischWerk – verbindliche Regeln für weitere Programmierungen

## Codex-Zugriff auf den integrierten Emulator

Der Emulator ist Bestandteil dieses MischWerk-Projekts: PROJEKT/tools/emulator, seine Prüfungen unter PROJEKT/tests/node/emulator.test.cjs und PROJEKT/tests/browser/emulator.browser.test.cjs. Der Nutzer muss künftig ausschließlich den MischWerk-Projektordner angeben. Bei beauftragten App-, Oberflächen- und Ablaufprüfungen diesen vorhandenen Emulator selbstständig als lokale Standard-Testumgebung verwenden; keinen zweiten Projektordner, ZIP-Pfad oder früheren Entpackordner anfordern.

Vom MischWerk-Hauptordner aus starten mit pnpm --dir PROJEKT run emulator; dieselbe vollständige Emulatorprüfung mit pnpm --dir PROJEKT run test:emulator ausführen. Innerhalb von PROJEKT gelten die bereits hinterlegten Befehle pnpm run emulator und pnpm run test:emulator. Alternativer direkter Einstieg vom Hauptordner: node PROJEKT/tools/emulator/server.cjs. Apppfad und benötigte Projektressourcen werden relativ zu den Werkzeugdateien ermittelt; keine absolute externe Emulatorablage konfigurieren. Fehlende Entwicklungsabhängigkeiten über pnpm --dir PROJEKT install --frozen-lockfile bereitstellen. Ein bereits passender lokaler Testserver darf wiederverwendet werden; fremde Prozesse und laufende Nutzertests erhalten.

Die ursprüngliche Browserstart-ZIP und frühere temporäre Prüfkopien werden zum Betrieb nicht benötigt. Der automatisch verwaltete Testdatenordner unter System-Temp ist ausschließlich Laufzeitzustand und kein zweites anzugebendes Projekt. Reine Dokumentations-/Ablageänderungen benötigen keinen Emulatorlauf. Appstand, lokale Simulationsgrenzen und tatsächliche Prüfungen weiterhin korrekt berichten.
